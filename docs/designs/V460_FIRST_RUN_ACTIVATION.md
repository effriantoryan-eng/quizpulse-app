## Vision

### 10x Check
A teacher signs up on their phone between periods. Ninety seconds later they have watched a
quiz they didn't have to write get answered by 24 practice students, seen the misconception
card light up ("8 students were confident but wrong — most picked the same wrong answer"),
and been handed the next move: create your real class and put its join code on the projector.
Every return visit opens with one question — "What do you want to check today?" — instead of
a five-hub navigation puzzle. (The projector code comes from the real class the checklist
walks them into creating — demo classes deliberately have no join code.)

### Platonic Ideal
During first-run, the teacher can upload the worksheet they taught that morning and QuizPulse
drafts a quiz from it (v4.3.0 pipeline, mock provider, zero LLM cost). First-run + AI drafting
+ demo class is a combination no incumbent offers. The landscape check confirms instant first
value is table stakes — and QuizPulse's push-first model structurally cannot deliver it with
real students, which makes the demo/simulation path the product's ONLY answer, deserving
first-class status. **Honesty constraint:** the mock provider produces template-shaped
questions; first-run copy frames drafts as "starting points you'll edit," never finished
quizzes. **Mobile caveat (OV#3):** worksheets live on laptops — the upload lane is expected
to be a desktop moment, and the fast lane must carry the phone experience alone.

## Strategic grounding
- GTM design doc (2026-06-28 /office-hours): no active users; next milestone is behavioral
  validation with real teachers. First-session activation is the gate to that milestone.
- D1: Tier 1+2 chosen over Tier-2-only and over an early Tier-3 IA rework.
- D10 (outside voice): E3/E4 trimmed to pilot-appropriate size — build the instrument and the
  content library when pilot n justifies them, not before.

## Engineering review addendum (2026-07-27, /plan-eng-review — D2–D11 below win on conflict)

Phasing (D2): **v4.6.0 activation core** = step-zero gate + Tier 2 + Tier 1 first-run + E3
generic pack + D12 sim fix + **E4 script (pulled in, D10)**. **v4.6.1 polish/probe** = E2 join
screen + E5 + E6.

Locked engineering decisions:
- **D3 — orchestration:** first-run chain is ONE server endpoint `POST /api/onboarding/first-run`
  (not client-orchestrated). All substep ids (demo class, quiz) derived from `teacherId`
  (materializeAi pattern); 409-tolerant; returns quizId to navigate to. Reuses the shared
  `createRealClass`/demo-class + quiz-create + `runSimulation` helpers, NOT the HTTP handlers.
- **D11 — simulation is an explicit final step** of that endpoint, calling `runSimulation`
  directly (not the `simulate-responses` HTTP endpoint); responses are present before the teacher
  lands on analytics; **instant arrival** (all 24 at once), no faked staggering. `runSimulation`'s
  existing 409-guard blocks double-simulate on resume.
- **D6 — resume logic is a pure function** over injected container fakes (runSimulation deps
  pattern), unit-testable offline, PLUS an integration retry test asserting zero dup demo
  classes/quizzes.
- **D4 — checklist state:** derive step-completion from live Cosmos counts; persist ONLY a
  dismiss flag (synthetic `getting_started` key via the featureIntros ETag-replace path). Also
  persist a per-step **skipped** marker (OV#3) so a deliberately-skipped step isn't re-run on
  resume and isn't confused with a failure.
- **D9 — checklist release:** the checklist stops owning PromoSlot once the **demo send
  completes (in-session) OR dismiss** — NOT first real send (that stays a visible step, not the
  release trigger). Feature-intro engine never dark-outs for days. Post-release the checklist
  renders as a normal, non-slot element until the real-send step ticks.
- **D7 + OV#12 — checklist perf:** compute checklist state inside `computeEligibleIntros`
  reusing the class/send counts it already runs (add only an approved-students count); short-
  circuit on the persisted release/dismiss **flag BEFORE any Cosmos read**, preserving v4.2.0's
  "dismissed → zero milestone queries" property.
- **D8 — Tier 2 persistence:** the existing v4.3 draft-status quiz doc IS the persistence layer.
  Build's "Save & go to send" creates the draft and navigates by quizId; Send/refresh resumes
  from the doc (reusing SendQuiz's existing quizId mode). NO sessionStorage mirror. (Draft
  cleanup for abandoned builds: note as a minor follow-up, not v4.6.0 scope.)
- **OV#9 — starter-seed endpoint named:** `POST /api/questions/starter-seed` (idempotent,
  teacher-scoped, `FEATURE_FIRST_RUN`-gated same as the finale per OV#11). Both the finale chain
  and the D6 empty-state CTA call it. Cross-tenant negative test targets this route.
- **OV#7/#8 — step zero split:** same-day **code gate** (E1 dogfood + 15MB proxy, v4.4 verify).
  ~~async infra track (custom domain)~~ **superseded — see post-review amendment below: the
  custom domain was dropped entirely, 2026-07-27.**
- **OV#13 — finale sequencing:** the first-run finale is pinned to the onboarded moment (after
  step 1 `POST /api/onboarding`), independent of profile completion; an early quitter still gets
  it. Profile PUT and the finale don't order-depend.
- **D5 + OV#5 — E4 query:** explicit `isDemo` two-bucket query (demo sends + real sends counted
  separately); does NOT reuse `rangeQuizStats` (it strips demo). The stale "reuses rangeQuizStats
  semantics" clause in Key implementation cautions §3 is DELETED.

## Design review addendum (2026-07-27, /plan-design-review — 6 decisions, D3–D7)

Focus: v4.6.0 activation-core screens (first-run finale + Getting Started checklist). Wireframe
in the house token language: `~/.gstack/projects/effriantoryan-eng-quizpulse-app/designs/v460-first-run-20260727/first-run-wireframe.html`.
Design binary unavailable (no OpenAI key on this machine); HTML wireframe used as the visual
reference. No DESIGN.md — calibrated against `quizpulse_mockups_v301.html` tokens.

- **D3 — payoff hierarchy (IA):** the first-run RESULT screen leads with the terracotta
  misconception hero card ("8 were confident but wrong — most picked X"), four-cell chart BELOW
  it. First-run only; regular `/teacher/analytics` keeps its existing four-cell → option-bars →
  hero order. The aha must land in second one, not after parsing a 2x2 grid.
- **D4 — send→result loading state:** one warm full-screen loader with staged copy ("Setting up
  your practice class…" → "Sending to 24 students…" → "Reading their answers…"), reusing the
  v4.3.0 GenerateQuiz staged-pending idiom, then cut straight to the D3 result. No fake latency
  (D11 is instant simulation); no bare spinner. Copy follows the no-jargon rule ("students", not
  "simulated responses").
- **D5 — skip affordance:** the finale keeps "I'll explore on my own" as a small muted TEXT link
  below the two lanes (never a button, never a peer third option). The ready-made lane is one tap
  and genuinely fast, so a low-friction primary path earns the right to de-emphasize the exit —
  escape hatch preserved (goodwill) without inviting bail-out before the aha.
- **D6 — mobile finale:** on mobile (the "phone between periods" viewport), collapse the upload
  lane to a one-line deferral ("Prefer to use your own worksheet? Do that later from a computer")
  and let the ready-made lane own the screen; desktop shows both lanes. Removes a dead-end
  affordance (worksheets live on laptops) on the make-or-break viewport.
- **D7 — checklist post-release placement:** after the checklist stops owning the promo slot
  (demo-send complete OR dismiss, per eng D9), it demotes to a slim collapsed strip at the bottom
  of Home ("Getting started: 2 of 5 ▸", expands on tap); the top promo slot returns to feature
  intros. Persists as a quiet progress anchor without monopolizing; fully dismissible.
- **Slop/copy fixes (folded, Pass 4):** drop the ✨ emoji from the E5 annotation (AI-slop
  blacklist #7 — emoji as design element); use a small terracotta label/dot instead. Checklist
  steps 4-5 (approve students / first real send) that can't complete in-session are framed as
  "coming up" (muted, numbered, not error-styled) so the checklist reads as a roadmap, not a
  stuck/broken state.

Visual-system notes (no decision needed): the finale extends the `ProfileWizardSteps` card idiom;
the checklist is a NEW component in the `FeatureIntroCard` purple-tint family (#F1EFFD) but
distinguished by a progress bar + tick-circle steps — related family, distinct function. Brand
purple (#534AB7) is the established primary, not gradient slop. Four-cell swatches reuse the
v4.0.0 accessibility posture (persistent legend, counts never hover-only).

## Accepted Scope (v4.6.0) — final specs

**Tier 1 — Guided first-run** (behind `FEATURE_FIRST_RUN` in `api/shared/features.js`).
Onboarding finale = create demo class + seed the generic starter pack + build quiz + guided
send → teacher watches simulated responses arrive on the analytics page. Chain is idempotent
(deterministic ids, 409-tolerant, resume from last completed step — materializeAi pattern),
every step skippable, one structured `context.log` line per step outcome; any failure
soft-lands on Home where the checklist shows the un-ticked step as the retry path.
**Getting Started checklist** owns PromoSlot until released (first real send OR explicit
dismiss, server-persisted); steps ≈ practice quiz ✓ / create your class (absorbs v4.2.0's
class-shells step — the wizard drops step 4, per D9) / share the join code (→ E2) / approve
students / first real send. **Demo simulation upgrade (D12):** `runSimulation.js` biases one
distractor per question and correlates confidence with it, so four-cell chart, hero card,
and per-option bars tell one coherent misconception story (unit test updated; mirrors-in-
runSimulation rule respected).

**Tier 2 — Unbreakable flow.** Build→Send quiz state persisted (sessionStorage mirror;
draft-doc option is eng review's call). Pending Requests without classId: auto-select the
single pending class, else in-place class picker.

**E1 — Doc-upload lane, gated BEFORE build (D13).** Step zero includes: founder dogfoods 3
real worksheets through `/teacher/generate` against deployed v4.3, AND the 15MB SWA-proxy
path verified live. Both pass → build the lane (secondary option in the finale, honest
"starting points you'll edit" copy). Either fails → E1 drops to TODOS with findings attached;
finale UI is designed to work with the lane absent.

**E2 — Projector join screen.** "Show join screen" on class cards + Roster →
`/teacher/classes/join-screen?classId=` — big-type join code, join URL on the
**`azurestaticapps.net` origin permanently (D15 dropped, 2026-07-27 — see amendment)**, QR
**mandatory** (vendored zero-dep encoder — no longer eng-vetoable, since the long URL alone is
a poor projector experience without it), copyable student-instruction snippet.

**E3 (trimmed) — One generic starter pack.** Five human-written, minors-safe, curriculum-
neutral questions (study-skills/general), reviewed like `apstContent.js`, seeded idempotently
into the teacher's own `questions` container (`origin:'starter'`, `visibility:'private'`,
counts toward cap, excluded from cross-teacher metrics via a shared fragment). Seeded during
the finale AND on demand via "Add 5 starter questions" CTA in Build/Question Bank empty
states (D6) — catches early quitters. Subject-matched packs: deferred (TODOS).

**E4 (trimmed) — Activation script.** A standalone founder-run script (populationSeed.js
convention: manual, never HTTP) computing the funnel from `teachers.createdAt` + `quizzes`
(`isDemo` split, `sentAt`): signups, demo sends, first real sends, median time-to-first-send.
No beacon changes; no admin panel yet (TODOS, pending pilot n). The funnel deliberately
counts demo sends — documented as a sanctioned exception in CLAUDE.md's demo-isolation
section + a comment at the query site (D5).

**E5 — First-result annotation via misconception_intro retarget (D14).** The existing key's
copy/placement upgrades to an anchored annotation on the first analytics view ("this is the
signal — here's what you'd do with it tomorrow"). No tenth key; no double-banner case.

**E6 — Home quick-start card.** Permanent non-promo card replacing the two quick-action
buttons: pick a topic (profile-prefiltered) or "start from a document" → Build with
auto-suggested name ("{Topic} check-in — {date}"), topic carried to Send; document option →
`/teacher/generate`. Topic is a name/Send prefill only — it does not (and cannot) filter the
question bank; the taxonomy unification stays out of scope (F6).

## Success metrics (restructured per D11)
- **Primary (pre-registered, absolute):** ≥50% of pilot-cohort teachers complete a first
  REAL (non-demo) send within 14 days of signup. Measured by the E4 script.
- **Flow health (monitoring, not success claims):** median signup→first-send time; funnel
  step completion/failure logs (D4); Build→send drop-off via route-level pageviews.
- Explicitly rejected: guided-flow completion rates as success evidence (true by
  construction), and baseline-uplift framing (no baseline exists — zero users).

## Key implementation cautions (prior learnings + review)
- `runSimulation.js` bypasses `POST /api/responses` — the D12 bias change lives INSIDE
  runSimulation; any submit-path side effect must be mirrored there (confidence 9/10).
- `usePageView` strips query params; its visitor ID is a device UUID — never join pageviews
  to teacher identity (confidence 9/10). E4's script reads containers only.
- Checklist eligibility extends `introEligibility.js` — no parallel engine. `origin:'starter'`
  exclusion is a single shared fragment (excludeDemo pattern). E4 script uses an explicit
  isDemo two-bucket query and does NOT reuse `rangeQuizStats.js` (see eng addendum D5/OV#5 —
  rangeQuizStats excludes demo, which would zero the funnel's demo-send stage).
- Wizard step-4 removal (D9) touches shipped v4.2.0 code — `POST /api/classes/shells` stays;
  only the wizard step moves; the shells call relocates to the checklist action.
